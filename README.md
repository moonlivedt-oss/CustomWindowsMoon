# Radial Menu

**PlayerMoon теперь входит в проект:** локальный аудиоплеер с библиотекой, очередью, визуализатором и текстами песен. Запуск: Студия → Стол → «Открыть PlayerMoon», палитра команд → PlayerMoon или пункт кольца с путём `{player}`. Управление треком — из обычной панели «Сейчас играет». [Устройство, сборка и проверка интеграции](docs/PLAYERMOON.md).

Объёмные значки для всех 13 тем и новый подборщик по назначению сектора: [156 значков, поиск и рекомендации](docs/design/illustrated-icons/README.md).

Новые знаки проектов и тематические иконки: [визуальная витрина](docs/design/identity/index.html), [описание и переключение палитр](docs/design/identity/README.md). Доступны Crimson, Aurora, Dusk и Sand; исходники SVG, рабочие PNG и многомасштабные ICO.

Круговое меню папок для Windows. Зажми **Alt** и доведи курсор до **левого или правого края** экрана: из края раскроется полукольцо. У каждого края свой набор секторов. Alt можно отпустить: кольцо остаётся на экране, пока курсор рядом.

## Управление

| действие | что делает |
|---|---|
| навести на сектор | раскрывает второе кольцо (содержимое папки или свой список), сверху карточка: что это, сколько внутри, когда менялось, где лежит |
| клик | выбрать (значок отзывается, внизу «Ещё раз - открыть») |
| двойной клик или Enter | открыть |
| тянуть кольцо с зажатой кнопкой | вращать: первое кольцо крутится по кругу и встаёт на ближайший сектор, второе прокручивается, если пункты не влезли (за краями тянется как резинка, брошенное на ходу докручивается) |
| Shift + открыть | открыть в VS Code |
| Ctrl + открыть | терминал в этой папке |
| Ctrl + Shift + открыть | показать в Проводнике |
| ПКМ по папке, колесо вверх | зайти внутрь (сверху появится путь) |
| ПКМ мимо, колесо вниз, Backspace, клик по центру | назад |
| колесо, стрелки | прокрутить второе кольцо, если пунктов много (полоса по внешнему краю показывает, где вы) |
| просто печатать | поиск по всем кольцам на два уровня вглубь; раскладка не важна: «ghjtrns» найдёт «Проекты» |
| Esc | очистить поиск, назад, закрыть |

**Перетаскивание файлов.** Тащишь файл, у края экрана зажимаешь Alt, бросаешь на сектор. На папку файл переносится или копируется (как в Проводнике, Shift и Ctrl выбирают сами). На программу или ярлык файл открывается в ней, на корзину удаляется. Если подержать файл над папкой, меню зайдёт в неё. Подсказка внизу показывает, что произойдёт.

**Оформление.** Под кольцом стекло: обои просвечивают с размытием. У каждой группы свой оттенок в пределах темы: тонкая полоса у внутреннего края сектора и подсветка его второго кольца. Подписи с мягкой тенью встают туда, где сектору просторнее, длинные имена переносятся на две строки (по пробелам, после дефиса, на стыке слов: «Auto / Translator»). Папки без своего значка получают значок проекта (`icon.png`, `logo.png`, `assets/icon.png`, значок из `package.json`, `app.ico`), а без него - бейдж типа по файлам в корне (C++, Python, веб, расширение VS Code, игра, скрипты, документы) или первую букву. Значки оживают при наведении: у корзины приподнимается крышка, стрелка загрузок падает в лоток, ракета вздрагивает, плитки программ поворачиваются. Акцент по умолчанию берётся из обоев (`accent = auto`). Тихие звуки при открытии и наведении, громкость настраивается.

## Горячие углы

У каждого угла три действия:

- **Задержать.** Курсор в углу около 250 мс: из угла растёт свечение с дугой ожидания, потом выполняется действие. Отвёл раньше, и ничего не будет.
- **Толкнуть дважды.** Два быстрых толчка курсором в угол (каждый короче задержки) выполняют второе действие.
- **Колесо.** Курсор в углу, крутишь колесо: яркость (внешний монитор через DDC/CI, экран ноутбука через WMI), общая громкость или треки (вверх следующий, вниз предыдущий). Уровень рисуется дугой и числом прямо в углу.

Действия: показать рабочий стол, все окна, Пуск, выключить экран, заблокировать, снимок области, пауза, следующий трек, без звука, любое сочетание клавиш (записывается в студии) или программа и файл. По умолчанию левый нижний угол показывает стол, а колесо там меняет яркость. Правый нижний открывает все окна, колесо в нём меняет громкость.

Углы не срабатывают с зажатым Alt (это кольцо), с нажатой кнопкой мыши и поверх игр на весь экран. Развёрнутое окно игрой не считается, даже если при скрытой панели задач оно закрывает весь экран.

## Сейчас играет

Доведи курсор до нижнего края экрана (не в угол): снизу выедет карточка с тем, что играет. Обложка, источник, название, исполнитель, полоса времени и кнопки. Цвет кнопки и полосы берётся из обложки, фон карточки - она же, размытая. Трек приходит из системных медиа-сеансов Windows, поэтому подходит любой плеер, в том числе музыка в браузере.

| действие | что делает |
|---|---|
| кнопки | назад, пауза, вперёд; «назад» дальше 3 секунд от начала перематывает в начало трека, кнопки, которые плеер сам выключил (нет очереди), гаснут |
| колесо над карточкой | громкость самого плеера (не всей системы) |
| клик по полосе | перемотать |
| клик по обложке или названию | открыть плеер |
| кнопка со строками | текст песни: карточка раскрывается вверх |
| клик по строке текста | перемотать к ней |
| переключатель сверху | если играют несколько программ, выбрать, какую показывать |
| ПКМ | текст песни, выключить панель |

Текст берётся с [lrclib.net](https://lrclib.net) (бесплатно, без ключей): синхронизированный подсвечивает текущую строку, обычный листается колесом. Для поиска туда уходят название и исполнитель трека. Из заголовков видео вроде «Control (Halsey) - Demon Slayer [AMV]» поиск сам вытаскивает название и исполнителя.

При смене трека снизу на 3 секунды выглядывает маленькая карточка; навёл на неё, и раскроется большая. Отключается в студии.

## Окна: прозрачность и поверх всех

Наведи курсор на верхнюю полосу любого окна (заголовок, вкладки):

| действие | что делает |
|---|---|
| Alt + колесо | прозрачность окна, шаг 5%, от 20% до 100% |
| Alt + средняя кнопка | закрепить поверх всех окон или открепить |

Рядом с окном всплывает подсказка с уровнем. Закреплённое окно получает тонкую рамку цвета темы. Действие для угла «Окно поверх всех» закрепляет активное окно. При выходе программы (или через пункт трея «Вернуть окнам прозрачность и закрепление») все окна возвращаются как были. Окна, запущенные от администратора, Windows менять не даёт, подсказка так и скажет. Выключается в студии, раздел «Стол».

## Кольцо окон

**Alt + ` (клавиша Ё)** открывает вокруг курсора кольцо открытых окон: то же, что Alt+Tab на текущем рабочем столе, по программам в порядке последнего использования. У программы с несколькими окнами второе кольцо раскрывается с их заголовками. В середине кольца живая миниатюра наведённого окна, внизу его полный заголовок.

| действие | что делает |
|---|---|
| отпустить Alt над сектором / клик | вывести окно вперёд (свёрнутое разворачивается) |
| средняя кнопка | закрыть окно, оно сразу пропадает из кольца |
| набор текста | поиск по названиям программ и заголовкам окон |
| Alt + ` ещё раз, Esc | закрыть кольцо |

То же кольцо можно повесить на горячий угол (действие «Кольцо окон»). Выключается в студии, раздел «Система».

## Кольцо в диалогах «Открыть» и «Сохранить»

Если впереди стандартный диалог выбора файла (в любой программе), кольцо не открывает Проводник, а работает с диалогом:

- **папка** - диалог переходит в неё, имя файла в поле остаётся прежним;
- **документ** - диалог переходит в его папку и подставляет имя, остаётся нажать Enter;
- **программы и ярлыки** (.exe, .lnk, .url, .bat) запускаются как обычно, Shift и Ctrl тоже работают как обычно.

Подсказка снизу пишет «Перейти сюда в диалоге». Старые диалоги «Обзор папок» (дерево без поля имени) не поддерживаются; мод Windhawk Modernize Folder Picker Dialog заменяет их обычным диалогом, и кольцо начинает работать и там.

## Профили

При первом открытии студии программа спрашивает, кто за компьютером: **Упрощённый**, **Разработчик** или **Специалист**. Профиль прячет лишнее в студии, меню трея и кольце утилит, но ничего не выключает. Сменить - щелчком внизу левой панели или в трее; «Показать всё» в строке снизу открывает скрытое, пока открыта студия. Подробности настройки появляются, если задержать на ней курсор.

## Сборка

```
build.cmd
```

Нужны MSYS2 ucrt64 (`g++`, `cmake`, `ninja`) в `D:\msys64`. Готовый `RadialMenu.exe` появляется в корне проекта рядом с `radial.cfg`.

Линкер пишет exe в `<папка сборки>\link`, а в рабочую папку он попадает только целым (`cmake/deploy.cmake`): проверка, что файл не пустой и начинается с `MZ`, копия рядом в `RadialMenu.exe.new`, её проверка и замена одним переименованием. Прерванная сборка больше не оставляет `RadialMenu.exe` в 0 байт: старый exe остаётся, а сборка падает с сообщением «Сборка испорчена: ...». Потом подпись (`cmake/sign.cmake`, если настроена) и отметка целостности (`cmake/integrity.cmake`) - уже с выложенного файла.

SHA-256 собранных `RadialTools.exe` и `RadialShutUp.exe` (уже подписанных) вшивается в `RadialMenu.exe`
(`cmake/ownhash.cmake` -> `gen/own_hashes.cpp`). Перед каждым запуском RadialMenu открывает файл без общего доступа на
запись (его не подменить между сверкой и запуском), сверяет хэш с вшитым (без вшитого - с отметкой целостности
сборки) и только потом запускает; не совпало - не запускает, пишет в журнал и показывает карточку «... подменён».
Проверка вручную: `RadialMenu.exe --own-check` -> `own_out.txt`.

`radial.cfg` у каждого свой и в репозиторий не входит: при первом запуске он копируется из `radial.example.cfg`
(кольца с Документами, Загрузками, Музыкой и другими общими папками), дальше всё настраивается в студии.

Проверочная сборка, не останавливая работающую копию: `cmake -S . -B build/check -G Ninja -DRADIAL_OUT_DIR=build/check`,
потом `cmake --build build/check`.

Свой код собирается с `-Werror`: любое предупреждение (например, `L"\*"` - неизвестная escape-последовательность) ломает сборку.

Тесты без окон (`tests/tests.cpp`: правило TEMP, разбор хода чистки, обход папок и папки-ссылки, живой рост, разбор MFT на синтетических записях - исправления секторов, куски с отрицательным смещением и разреженные, DOS- и Win32-имена, жёсткие ссылки, записи-продолжения, ссылки, таблица папок, её файл и индекс в памяти, сверка файлов в корне, вывод DISM и проценты хода, ротация журнала, находки автозапуска, дампы падений, рост своей памяти, фоновые задачи):

```
build.cmd test
```

собирает и прогоняет их, не трогая работающий `RadialMenu.exe`; упали - код ошибки. Вручную: `cmake --build build/check --target radial_tests`, потом `ctest --test-dir build/check`.

```
build.cmd lint
build.cmd snaps
```

`lint` - clang-tidy по всему `src` (проверки на ошибки из `.clang-tidy`, без стиля). `snaps` - эталонные снимки студии:
девять разделов (среди них вкладки «Утилит» PATH и «Диски», «Сеть» - скорость и Wi-Fi) и кольцо утилит с раскрытой «Защитой» (`--tools-ring-snap
файл 4 demo` - выдуманные пункты) снимаются в `build/check` с выдуманными данными (`RADIAL_DEMO=1`) и сравниваются с `tests\snaps`
попиксельно (порог 0,5%); разница - картинкой `build\check\snaps\<раздел>-diff.png`, итог - `snaps_out.txt`.
`build.cmd snaps update` - записать нынешние снимки как эталоны.

Отладочные сообщения окну программы (`WM_APP + 50..58`, `66..68`: кольца, портал, карточки на выдуманных данных)
принимаются только при `RADIAL_DEV=1` или файле `dev.on` рядом с exe - иначе их мог бы послать любой процесс.

Установщик для других людей - набор `radialmenu` в Moon bundle:
`node build.js radialmenu --test` (проверка в песочнице; работающую RadialMenu на время закрыть - установщик
ждёт её закрытия), архив - `dist\radialmenu-install.zip`. Свой `radial.cfg`, бэкапы, исходники и картинки `art` в
него не попадают.

## Защита репозитория

- **Секреты.** `.github/workflows/secrets.yml` на каждый push и pull request прогоняет gitleaks по всей истории
  (`fetch-depth: 0`): версия gitleaks и SHA-256 его архива закреплены в файле, `actions/checkout` - по коммиту.
  Нашлось - проверка красная, в журнале шага - где (сами значения скрыты, `--redact`). Исключение одно
  (`.gitleaks.toml`): выдуманные ключи и токены в `tests/tests_*.cpp` - образцы для детектора секретов и разбора
  файла телефонов.
- **Личное.** `tools/check-personal.ps1` ищет в изменениях имя пользователя Windows, имя ПК, текущую и сохранённые
  сети Wi-Fi и свои метки из файла вне репозитория (`%APPDATA%\MoonDesk\personal-markers.txt`, по метке в строке,
  `#` - комментарий; файл внутри репозитория скрипт читать отказывается). Перед коммитом - без ключей (подготовленное),
  перед push - `-Range origin/main..HEAD` (строки, имена файлов, сообщения и авторы коммитов), `-WorkTree` - всё
  незакоммиченное. Найденное - «файл:строка» с меткой под звёздочками, код выхода 1.

```bash
powershell -ExecutionPolicy Bypass -File tools/check-personal.ps1 -Range origin/main..HEAD
```

Чтобы проверка шла сама: `tools/install-hooks.ps1` ставит в `.git/hooks` pre-commit (подготовленное) и pre-push
(уходящие коммиты); нашлось - коммит или push не выполняется (разово обойти - `--no-verify`). Чужой хук не
перезаписывается без `-Force`.

```bash
powershell -ExecutionPolicy Bypass -File tools/install-hooks.ps1
```

tests/                     тесты radial_tests и эталонные снимки студии (tests/snaps)

android/                   приложение «Компьютер рядом»

build/                     все сборки: main - основная, check - проверочная, out - итоги dev-режимов
```

             экран блокировки и портал, фон «Пуска», значки папок, показ экрана без личного (share)
  media/     «Сейчас играет» (media, widget), тексты песен, громкость, громкость по программе, связь с PlayerMoon
  helpers/   помощники по действию: история буфера, снимок и OCR, пипетка, предпросмотр, запись экрана,
             конвертер, полка, напоминания, «Не спать», порядок на столе, палитра команд, продолжить работу,
             сон после работы
  cards/     карточки справа снизу: основа (toast), журнал карточек, карточки Boost, сети и сцены
  net/       сеть: пробы, проверка и починка, сторож связи, защита VPN, безопасность, выход VPN по пингу
  phone/     «Телефон рядом»: сервер, страница (phone/web), TLS, файлы, пульт, экран
  system/    системные утилиты (namespace tools): диски, MFT, PATH, автозагрузка, порты, процессы,
             «Защита», здоровье, обновления winget; system/ui - кольцо утилит и его действия (toolsui*);
             system/auto - автоматика: тихая чистка, Загрузки, самовосстановление, недельный отчёт,
             ночные обновления, забота о батарее, наушники, камера и микрофон
  radialtools/  RadialTools.exe: удаление и завершение процессов по команде (основной exe этого не делает)
  shutup/    RadialShutUp.exe: настройки приватности Windows
  res/       значок, манифест, ресурсы
```

Файлы `*_logic.cpp` - чистая часть модуля без окон и системы, она под тестами. Пространства имён по старой памяти
могут не совпадать с папкой (код `system/` - в `namespace tools`).

Новые `.cpp` подхватываются сборкой сами (CMake собирает всё из `src`).

### Падения

Необработанное исключение, `std::terminate` и `abort` пишут минидамп (`MiniDumpWriteDump`, dbghelp только из System32) и строку «код, что это, модуль+смещение» рядом в `%APPDATA%\MoonDesk\crash\crash-<дата>-<время>-<pid>.dmp/.txt`, хранятся последние 5 (`core/crash`). При следующем запуске - строка в журнале автоматики и карточка «Программа падала» с кнопкой «Папка»; о каждом дампе - один раз (отметка `reported` в той же папке). Проверка: `RadialMenu.exe --crash-test` нарочно падает. После падения (если программа прожила больше минуты) поднимается новая копия с `--after-crash` - она ждёт, пока старая освободит мьютекс; при обычном выходе и конце сеанса перезапуск выключается первым делом, а сам выход - `TerminateProcess` после `ShutdownAll`, без разрушения глобальных объектов (они держали картинки GDI+ и падали в gdiplus.dll). Вторая обычная копия рядом с работающей сразу выходит.

Своя память: слежка раз в час пишет в журнал автоматики рабочий набор, частные байты, число дескрипторов, GDI- и USER-объектов (`system/selfwatch`); за сутки частные байты выросли больше чем на 300 МБ, дескрипторы на 3000 или GDI/USER на 1500 - карточка «RadialMenu растёт» (не чаще раза в сутки, не в игре).

Разбор адреса: сборка, пока exe ещё с символами, пишет карту `nm` в
`%APPDATA%\MoonDesk\integrity\maps\RadialMenu-<метка>.map` (10 последних, `cmake/symbols.cmake`), потом убирает
символы из exe. Строка падения несёт ту же метку («... в RadialMenu.exe+0x4fd40, сборка 6ADA197A» - TimeDateStamp
заголовка PE), карточка «Программа падала» и журнал автоматики сразу пишут функцию («функция devcli::Run(int&)+0xf60»).
Вручную: `RadialMenu.exe --crash-decode ["строка"]` -> `crash_out.txt` (без строки - все падения из папки crash).

Код и смещение падения - ещё и в журнале Windows (Приложение, событие 1000). Сборка с символами для разбора адреса:
`cmake -S . -B build-sym -G Ninja -DRADIAL_STRIP=OFF -DRADIAL_OUT_DIR=<папка>`, затем `nm -C --defined-only` и ближайший
адрес ниже `0x140000000 + смещение`. Студия не рисует кадр внутри кадра: COM и WMI (здоровье дисков, планировщик)
прокачивают сообщения, вложенный WM_PAINT откладывается; WMI - в своём потоке.

### Замеры

`set RADIAL_PROFILE=1` перед запуском: при выходе рядом с exe появится `profile.log` со временем основных операций
(кадр меню, открытие, снимок под стекло, кадр студии по разделам, `poll` - такт опроса основного потока). Строки
`cpu.*` - время процессора фоновых проходов, а не настенное (`PERF_CPU`): `cpu.scan` - подсчёт места (в нём
`cpu.scan.sys` - суточная часть), `cpu.security` - «Защита», `cpu.weekly` - недельные проверки, `cpu.guard` - проход
сторожей процессов, `cpu.watch` - минутная слежка.

Тяжёлое после входа идёт по очереди (Н9): кэши и проекты - через 90 с, «Защита» - через 4 мин, суточная часть - через
7 мин, недельные проверки - через 10 мин. От батареи обход кэшей, суточная часть, «Защита» и недельные проверки ждут
зарядки, но не дольше суток с прошлого раза (время - в `%APPDATA%\MoonDesk	ools\weekly.ini`, секция `heavy`);
лёгкие части (PATH) идут как обычно, по кнопкам в студии - всегда. Итог обхода кэшей и проектов лежит в
`%APPDATA%\MoonDesk\tools\scan-cache.tsv`: перезапуск в пределах 3 часов берёт его, а не обходит заново. `set RADIAL_ON_BATTERY=1` - считать, что от
батареи (проверка без выдёргивания зарядки).

`set RADIAL_SNAP=1`: каждый кадр панели «Сейчас играет» сохраняется в `media_snap.png` рядом с exe.
