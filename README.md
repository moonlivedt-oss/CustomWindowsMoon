# Radial Menu

Круговое меню папок для Windows. Зажми **Alt** и доведи курсор до **левого или правого края** экрана: из края раскроется полукольцо. У каждого края свой набор секторов. Alt можно отпустить: кольцо остаётся на экране, пока курсор рядом.

## Управление

| действие | что делает |
|---|---|
| навести на сектор | раскрывает второе кольцо (содержимое папки или свой список), сверху карточка: что это, сколько внутри, когда менялось, где лежит |
| клик | выбрать (значок отзывается, внизу «Ещё раз - открыть») |
| двойной клик или Enter | открыть |
| тянуть кольцо с зажатой кнопкой | вращать: первое кольцо крутится по кругу и встаёт на ближайший сектор, второе прокручивается, если пункты не влезли (за краями тянется как резинка, брошенное на ходу докручивается) |
| Shift + открыть | открыть в VS Code |
| Ctrl + открыть | терминал в этой папке |
| Ctrl + Shift + открыть | показать в Проводнике |
| ПКМ по папке, колесо вверх | зайти внутрь (сверху появится путь) |
| ПКМ мимо, колесо вниз, Backspace, клик по центру | назад |
| колесо, стрелки | прокрутить второе кольцо, если пунктов много (полоса по внешнему краю показывает, где вы) |
| просто печатать | поиск по всем кольцам на два уровня вглубь; раскладка не важна: «ghjtrns» найдёт «Проекты» |
| Esc | очистить поиск, назад, закрыть |

**Перетаскивание файлов.** Тащишь файл, у края экрана зажимаешь Alt, бросаешь на сектор. На папку файл переносится или копируется (как в Проводнике, Shift и Ctrl выбирают сами). На программу или ярлык файл открывается в ней, на корзину удаляется. Если подержать файл над папкой, меню зайдёт в неё. Подсказка внизу показывает, что произойдёт.

**Оформление.** Под кольцом стекло: обои просвечивают с размытием. У каждой группы свой оттенок в пределах темы: тонкая полоса у внутреннего края сектора и подсветка его второго кольца. Подписи с мягкой тенью встают туда, где сектору просторнее, длинные имена переносятся на две строки (по пробелам, после дефиса, на стыке слов: «Auto / Translator»). Папки без своего значка получают значок проекта (`icon.png`, `logo.png`, `assets/icon.png`, значок из `package.json`, `app.ico`), а без него - бейдж типа по файлам в корне (C++, Python, веб, расширение VS Code, игра, скрипты, документы) или первую букву. Значки оживают при наведении: у корзины приподнимается крышка, стрелка загрузок падает в лоток, ракета вздрагивает, плитки программ поворачиваются. Акцент по умолчанию берётся из обоев (`accent = auto`). Тихие звуки при открытии и наведении, громкость настраивается.

## Горячие углы

У каждого угла три действия:

- **Задержать.** Курсор в углу около 250 мс: из угла растёт свечение с дугой ожидания, потом выполняется действие. Отвёл раньше, и ничего не будет.
- **Толкнуть дважды.** Два быстрых толчка курсором в угол (каждый короче задержки) выполняют второе действие.
- **Колесо.** Курсор в углу, крутишь колесо: яркость (внешний монитор через DDC/CI, экран ноутбука через WMI), общая громкость или треки (вверх следующий, вниз предыдущий). Уровень рисуется дугой и числом прямо в углу.

Действия: показать рабочий стол, все окна, Пуск, выключить экран, заблокировать, снимок области, пауза, следующий трек, без звука, любое сочетание клавиш (записывается в студии) или программа и файл. По умолчанию левый нижний угол показывает стол, а колесо там меняет яркость. Правый нижний открывает все окна, колесо в нём меняет громкость.

Углы не срабатывают с зажатым Alt (это кольцо), с нажатой кнопкой мыши и поверх игр на весь экран. Развёрнутое окно игрой не считается, даже если при скрытой панели задач оно закрывает весь экран.

## Сейчас играет

Доведи курсор до нижнего края экрана (не в угол): снизу выедет карточка с тем, что играет. Обложка, источник, название, исполнитель, полоса времени и кнопки. Цвет кнопки и полосы берётся из обложки, фон карточки - она же, размытая. Трек приходит из системных медиа-сеансов Windows, поэтому подходит любой плеер, в том числе музыка в браузере.

| действие | что делает |
|---|---|
| кнопки | назад, пауза, вперёд; «назад» дальше 3 секунд от начала перематывает в начало трека, кнопки, которые плеер сам выключил (нет очереди), гаснут |
| колесо над карточкой | громкость самого плеера (не всей системы) |
| клик по полосе | перемотать |
| клик по обложке или названию | открыть плеер |
| кнопка со строками | текст песни: карточка раскрывается вверх |
| клик по строке текста | перемотать к ней |
| переключатель сверху | если играют несколько программ, выбрать, какую показывать |
| ПКМ | текст песни, выключить панель |

Текст берётся с [lrclib.net](https://lrclib.net) (бесплатно, без ключей): синхронизированный подсвечивает текущую строку, обычный листается колесом. Для поиска туда уходят название и исполнитель трека. Из заголовков видео вроде «Control (Halsey) - Demon Slayer [AMV]» поиск сам вытаскивает название и исполнителя.

При смене трека снизу на 3 секунды выглядывает маленькая карточка; навёл на неё, и раскроется большая. Отключается в студии.

## Окна: прозрачность и поверх всех

Наведи курсор на верхнюю полосу любого окна (заголовок, вкладки):

| действие | что делает |
|---|---|
| Alt + колесо | прозрачность окна, шаг 5%, от 20% до 100% |
| Alt + средняя кнопка | закрепить поверх всех окон или открепить |

Рядом с окном всплывает подсказка с уровнем. Закреплённое окно получает тонкую рамку цвета темы. Действие для угла «Окно поверх всех» закрепляет активное окно. При выходе программы (или через пункт трея «Вернуть окнам прозрачность и закрепление») все окна возвращаются как были. Окна, запущенные от администратора, Windows менять не даёт, подсказка так и скажет. Выключается в студии, раздел «Стол».

## Кольцо окон

**Alt + ` (клавиша Ё)** открывает вокруг курсора кольцо открытых окон: то же, что Alt+Tab на текущем рабочем столе, по программам в порядке последнего использования. У программы с несколькими окнами второе кольцо раскрывается с их заголовками. В середине кольца живая миниатюра наведённого окна, внизу его полный заголовок.

| действие | что делает |
|---|---|
| отпустить Alt над сектором / клик | вывести окно вперёд (свёрнутое разворачивается) |
| средняя кнопка | закрыть окно, оно сразу пропадает из кольца |
| набор текста | поиск по названиям программ и заголовкам окон |
| Alt + ` ещё раз, Esc | закрыть кольцо |

То же кольцо можно повесить на горячий угол (действие «Кольцо окон»). Выключается в студии, раздел «Система».

## Кольцо в диалогах «Открыть» и «Сохранить»

Если впереди стандартный диалог выбора файла (в любой программе), кольцо не открывает Проводник, а работает с диалогом:

- **папка** - диалог переходит в неё, имя файла в поле остаётся прежним;
- **документ** - диалог переходит в его папку и подставляет имя, остаётся нажать Enter;
- **программы и ярлыки** (.exe, .lnk, .url, .bat) запускаются как обычно, Shift и Ctrl тоже работают как обычно.

Подсказка снизу пишет «Перейти сюда в диалоге». Старые диалоги «Обзор папок» (дерево без поля имени) не поддерживаются; мод Windhawk Modernize Folder Picker Dialog заменяет их обычным диалогом, и кольцо начинает работать и там.

## Стол и система

- **Двойной клик по пустому столу** открывает целое кольцо вокруг курсора: секторы левого и правого края вместе, первый сверху, дальше по часовой.
- **Заряд.** Когда заряда меньше 15% (настраивается), у нижнего края тихо дышит свечение цвета темы; подключил зарядку - по краю пробегает светлая волна.
- **Снимок области.** После Win+Shift+S справа снизу выезжает карточка с превью: «Сохранить» кладёт PNG в «Снимки экрана», «Текст» распознаёт снимок встроенным OCR Windows и кладёт текст в буфер. Клик по превью открывает снимок.
- **Ночной режим** (по умолчанию с 23 до 7): стекло карточек темнее, свечения спокойнее, звуки вдвое тише.
- **Курсор**: цвет заливки (акцент, серебро, сталь, свой) и размер. Курсоры перекрашиваются на время работы программы, в реестр ничего не пишется.
- **Тема везде** (первая карточка раздела «Система»): одна кнопка применяет тему ко всему, что стоит: моды Windhawk одним .reg (Проводник, центр уведомлений, Параметры, поиск) и Пуск Start11. Проводник при этом перезапускается.
- **Меню Пуск** (Stardock Start11): фон из размытого куска обоев под плотной вуалью темы, подложка меню - графит с каплей акцента, кнопка Пуск перекрашена из «Triangle Two» (серебро и сталь, открытое меню - акцент, картинка в %APPDATA%\MoonDesk\start-button.png). Меню и кнопку Start11 рисует внутри Проводника, поэтому после применения Проводник перезапускается.
- **Параметры** (мод Windows 11 Settings Styler) и **поиск Windows** (мод Windows 11 Start Menu Styler, тема TintedGlass): графитовое стекло с каплей акцента.
- **Значки папок** (мод Windhawk Resource Redirect): копия текущей темы значков, где сиреневые папки стали графитовыми, а рисунки на них - цвета акцента. Тема собирается в %APPDATA%\MoonDesk\icons.
- **Центр уведомлений** (мод Notification Center Styler): тема TintedGlass с цветами темы.
- **Проводник** (мод Windows 11 File Explorer Styler): своя тема без встроенных - вкладки и панель команд в графитовом стекле с каплей акцента, тонкая акцентная кромка у адресной строки, подсказок и меню «...»; Mica только на рамке, чтобы список файлов оставался сплошным тёмным. Для проверки: `RadialMenu.exe --explorer-reg` (а также `--notify-reg`, `--settings-reg`, `--search-reg`, `--all-reg`) пишет .reg по текущей теме в %APPDATA%\MoonDesk, `--start-apply` оформляет Пуск.

Настройки модов Windhawk лежат в системной части реестра, поэтому студия готовит .reg-файл: Windows спросит разрешение, затем мод нужно выключить и включить в Windhawk.

Тема **«Багровое поле»**: графит грозового неба, багровый акцент, сталь и серебро - под обои с красными цветами.

## Красота и игровой режим

- **Живая рамка окна.** При переключении рамка нового окна вспыхивает светлым акцентом и оседает в цвет темы, у прежнего плавно гаснет до стали. Работает для любых программ через DWM, без внедрения в процессы.
- **Заголовки под тему.** Полоса заголовка у всех окон графитовая, текст светлый, у неактивных окон приглушён. Окна, которые рисуют заголовок сами (браузер, VS Code, новый Блокнот), меняют только рамку.
- **Кольцо.** Раскрывается пружиной, секторы второго кольца проявляются волной от середины, наведённый сектор выдвигается наружу, а запущенный пункт уходит волной от сектора, пока меню гаснет (клики в это время проходят насквозь).
- **Движение.** Одна настройка скорости для всех анимаций программы: спокойно, обычно, живо.
- **Цвета по времени суток** (на снимках с `RADIAL_DEMO` выключены - эталоны не зависят от часа; `day_tint`, «Система» - «Ночной режим»): днём акцент чуть ярче, за 5 часов до ночи цвета теплеют, в часы ночного режима тёплые и фон темнее, после ночи 3 часа остывают. Кромка колец немного берёт цвет обоев, если акцент темы не из них. Меняется вся тема разом (`DayTint` в `CurrentTheme`).
- **Экран блокировки** («Применить» в студии): обои или своя картинка подгоняются под экран и красятся под тему: тени уходят в графит, цвета, далёкие от акцента, притихают, края темнеют, сверху вуаль под часы, у нижнего края световой шов цвета акцента, как у колец. Картинка ставится через WinRT, прав администратора не нужно (`%APPDATA%\MoonDesk\lockscreen-theme.jpg`).
- **Ввод пароля.** Под аватаром и полем пароля картинка мягко затемнена, чтобы они читались. «Чёткий фон вместо размытого» убирает матовое стекло Windows с экрана входа (политика `DisableAcrylicBackgroundOnLogon` в HKLM, поэтому через .reg с подтверждением). «Аватар в стиле колец» рисует картинку для круга над полем: графит, кольцо секторов с одним багровым «наведённым» сектором, в середине полумесяц или своя картинка (`avatar_source`). Ставить аватар сама Windows разрешает только через Параметры: студия кладёт путь в буфер и открывает «Ваши данные», остаётся «Обзор файлов», Ctrl + V, Enter. Само поле и шрифты рисует LogonUI на защищённом столе, их не трогаем.
- **Переход блокировки.** При блокировке за экраном блокировки заранее встаёт копия его картинки (размытая или чёткая, как у экрана входа). После входа - «портал» (около 2 с): портал раскрывается оттуда, где курсор. Сначала на стекле проступает узор, вокруг курсора по одному, по часовой, встают секторы кольца, последним с вспышкой - багровый «наведённый»; потом фронт идёт к краям экрана. С узором стекло рассыпается по ячейкам: каждая сжимается к своей середине и гаснет, ячейки на фронте горят кромкой цвета акцента. Соты возле курсора приподнимаются, пока зажигается кольцо, а перед фронтом бежит волна приподнятых: грани, обращённые к курсору, ловят свет, противоположные и швы под ними уходят в тень. Узоры: «Соты» и «Осколки» (витраж с трещинами, `lock_pattern = hex | shards | none`); без узора - круглый вырез с тенью и бегущей по кромке искрой. Кольцо идёт впереди фронта и поворачивается, с фронта срываются искры, звучит тихий подъём с колокольчиками (если звуки включены). Кадр считается за 9 мс, узор - один раз при блокировке за 50 мс. Можно выбрать простое растворение (`lock_anim = fade`). Блокировка из горячего угла проигрывает портал назад - он схлопывается в угол. Посмотреть - «Показать» в студии.

**Сотовое стекло** (`hex_glass`) - общий стиль для всего, что связано с порталом:

- **Углы.** Пока курсор ждёт в углу, из угла веером загораются соты, сота у фронта чуть больше - встаёт на место; при срабатывании все вспыхивают светлым.
- **Кольцо.** По секторам идут тонкие грани сот, каждая сота чуть своей яркости; сота под курсором приподнята (светлее, с яркой кромкой), соседние подсвечены.
- **Зарядка.** Вместо светлой волны по нижнему краю бежит волна сот: у фронта они встают выше и горят ярче, позади гаснущий след.
- **Игровой режим.** При включении и выключении от середины нижнего края по периметру экрана в обе стороны бегут загорающиеся соты (включение - акцентом, выключение - сталью), внизу на пару секунд плашка «Игровой режим: игра» или «Игровой режим выключен». Поверх эксклюзивного полноэкранного режима не показывается.

Портал работает не только после разблокировки:

- **При входе после включения** (`boot_portal`): если программа запустилась вместе со входом в Windows (Проводник стартовал меньше полутора минут назад), картинка проступает поверх стола и раскрывается порталом.
- **После сна и выключения экрана** (`wake_portal`): действие угла «Выключить экран» сначала схлопывает портал в угол, потом гасит экран; перед сном картинка встаёт заранее. Когда экран включится (или после пробуждения придёт ввод), стол открывается порталом. Если при этом сработала блокировка, портал ждёт входа.

**Игровой режим** выключает всю красоту, пока запущена игра: анимации колец и карточек мгновенные, без стекла, свечений заряда, панели «Сейчас играет» и рамок окон, перехват мыши для углов и окон снимается. Заодно (каждое по отдельности) выключаются анимации и прозрачность Windows и ставится на паузу Wallpaper Engine; после выхода из игры всё возвращается как было. Если программа упадёт посреди игры, при следующем запуске она вернёт настройки сама (`%APPDATA%\MoonDesk\gamemode.ini`).

**Режим разработки** включается сам, пока открыт тяжёлый редактор (`dev_apps`, по умолчанию `UnrealEditor.exe|UE4Editor.exe`): Wallpaper Engine ставится на паузу, а при запуске редактора приходит карточка «освободить память» (тот же Boost, что перед игрой); после закрытия редактора закрытое можно вернуть. В отличие от игрового режима анимации, углы и кольца работают. Включить вручную - в меню значка в трее, настройки - студия, Стол - Красота. Редактор из папки `Epic Games` игрой не считается. Поставленные на паузу обои записываются в `%APPDATA%\MoonDesk\devmode.ini`.

**Память перед игрой (Boost).** Логика скриптов `D:\Desktop\components\Boost` перенесена внутрь, конфиг общий - `boost.config.json` (белый список, защищённые, что чистить), так что скрипты и меню Boost работают и дальше.

- При запуске игры (если по `minFreePercent` памяти мало и закрывать есть что, от 150 МБ) справа снизу выезжает карточка «Освободить ~1.2 ГБ перед игрой?» со списком программ (имена из описания файла). Без клика ничего не закрывается; карточка не отнимает фокус у игры.
- «Освободить»: программы закрываются мягко (WM_CLOSE, как крестик), через `gracefulTimeoutMs` добиваются; при `trimWorkingSet` сжимаются рабочие наборы, при `purgeStandby` чистится кэш памяти. Итог - «Освобождено 1.1 ГБ». Закрытое пишется в `boost.session.json` в формате Boost (`GameBoost -Restore` тоже сможет вернуть).
- Пока идёт игра: таймер 0.5 мс (`timerResolution`), пониженный приоритет процессов из `deprioritize`, Game DVR выключен (`disableGameDvr`).
- После игры: приоритеты и таймер возвращаются, память чистится ещё раз, карточка предлагает вернуть закрытые программы (открываются свёрнутыми).
- Очистке кэша нужны права администратора: в студии «Очистка кэша без запросов - Настроить» один раз создаёт задачу планировщика `MoonRadial\RadialMenuPurge` (Windows спросит разрешение), дальше она запускается без запросов (`RadialMenu.exe --purge` из папки помощника, см. «Задачи с правами»). Какие области чистить, задача получает запросом в `HKCU\Software\MoonRadial`, а не из настроек рядом с exe. После пересборки программы задача ждёт «Пересоздать»: сама после игры она старую копию не запускает и UAC не спрашивает.
- Вручную: пункт трея «Освободить память...», действие угла «Освободить память», кнопка в студии.

Игрой считается программа из папок по маскам `games` (по умолчанию все игры Steam, Epic, EA, Wuthering Waves, NFS14.exe; `games_skip` - исключения вроде Wallpaper Engine) или всё, что идёт в эксклюзивном полноэкранном режиме. Вручную режим включается и выключается в меню значка в трее; выключенный посреди игры не включится снова, пока она не закроется.

## Сеть

Наследник [NetworkDoctor](../NetworkDoctor), но внутри колец и без Python и PowerShell: всё на функциях Windows (WinHTTP, IP Helper, ICMP, COM брандмауэра), в фоновых потоках.

- **Кольцо «Сеть»** - действие угла (например, правый верхний): «Починить умно», «Сбросить прокси», «Остатки VPN», DNS (самый быстрый, Cloudflare, Google, от роутера, очистить кэш), прокси-процессы (двойной клик завершает), пинг, «Обновить IP», «Проверить сеть» (открывает студию). Внизу строка состояния: есть ли интернет, страна выхода, задержка, через какой туннель. Действия идут в фоне, ход и итог - в карточке справа снизу.
- **Сторож** (`net_watch`): раз в `net_interval` секунд лёгкий HTTPS-запрос, как ходит браузер. Пропал интернет - короткая диагностика и карточка с причиной и одной кнопкой («Сбросить прокси», «Починить», «Убрать остатки», «Обновить IP»); сама сеть не трогается. Вернулся - «Интернет вернулся, не было N мин». После сна и разблокировки обрыв первые 25 с не считается. `net_exit` - карточка, когда выход сменился («Финляндия -> США»).
- **Игры** (`net_game`): через 20 с после старта игры смотрим её TCP-соединения, адрес сервера, маршрут и задержку. Если игра идёт через туннель или пинг выше 100 мс - карточка с советом.
- **Студия, раздел «Сеть»**: проверка карточками, совет, починка (прокси, остатки VPN, IP, адаптер, откат брандмауэра, глубокий сброс), DNS адаптера и замер DNS, права, сторож, прокси-процессы, история (`%APPDATA%\MoonDesk
et\history.txt`).
- **Скорость** (пункт кольца «Сеть», `net/speed`): задержка повтором HTTPS, загрузка (10 МБ, на быстрой сети ещё
  100 МБ, до 8 с) и отдача (5-25 МБ) через speed.cloudflare.com - как ходит браузер, то есть через туннель, если он
  включён. Каждый замер помнит, шёл ли он через туннель и через какую страну (`%APPDATA%\MoonDesk\net\speed.tsv`,
  200 замеров); когда есть замеры и с туннелем, и без - «обычно через туннель ↓ 80, напрямую ↓ 140» (медианы
  последних 20 каждого вида). Без окна: `RadialMenu.exe --speed-test` -> `speed_out.txt`. Раз в сутки замер идёт
  и сам (`speed_auto`, «Сеть» - «Сторож»): компьютер простаивает 5 минут, не игра и не Unreal, без карточки.
- **Wi-Fi** (пункт кольца «Сеть», `net/wifi`, Native Wifi API без прав): сигнал, канал, соседние сети на том же и
  перекрывающихся каналах (2,4 ГГц - ближе 5 каналов), совет по каналу; «QR для телефона» - картинка с паролем
  сохранённой сети (свой кодировщик `gfx/qr`, сверен с библиотекой qrcode бит в бит на версиях 1-10), файл удаляется
  через 2 минуты. Windows 11 отдаёт сигнал и соседей только при включённом определении местоположения - без него
  пункт открывает нужную страницу Параметров, а QR всё равно работает (имя сети - из списка сетей Windows, «Сеть 2»
  сводится к профилю «Сеть»). Без окна: `--wifi-diag` -> `wifi_out.txt`, `--qr-dump текст` -> `qr_out.txt`.
- **Скорость и Wi-Fi в студии** («Сеть», `studio_net_live.cpp`): столбики загрузки и отдачи по дням (медианы дня,
  через туннель - цвет темы, напрямую - зелёный; при наведении - день, задержка, сколько замеров), медианы обоих
  видов и «Замерить» со спидометром: стрелка на логарифмической шкале 1-1000 Мбит/с идёт за мгновенной скоростью,
  под ней шаги «задержка - загрузка - отдача» наполняются по ходу. Wi-Fi - схема каналов: ось 2,4 ГГц (1-13) и
  5 ГГц (ряд стандартных каналов), каждая сеть - колокол шириной в 20 МГц, высота - сигнал, своя - цветом темы,
  наведение - имя, сигнал, канал; «QR для телефона» и «Послушать снова». Без местоположения - честная карточка с
  «Открыть Параметры» и QR. Снимки: `RADIAL_DEMO=1 --studio-snap 6 0`, `RADIAL_SPEED=live` - спидометр посреди
  замера, `RADIAL_WIFI=off` - без местоположения.

Отличия от NetworkDoctor:

- Прежде чем назвать прокси «застрявшим», проверяем, жив ли он. Жив, но сайты не открываются - совет «сменить сервер в клиенте», а не сброс, который выключил бы клиент. Сброс при живом прокси всегда спрашивает.
- TUN-режим (Happ, sing-box) сам отвечает на пинг и DNS за 0 мс. Такие ответы считаются подделкой: задержка меряется повтором HTTPS-запроса по открытому соединению (круг до выхода туннеля), замер DNS честно говорит, что через туннель он бессмыслен.
- «Остатки VPN» удаляют только правила брандмауэра, похожие на kill-switch (с бэкапом `.wfw`), а не сбрасывают весь брандмауэр.
- Действия с правами - через задачу планировщика `MoonRadial\RadialMenuNet` (`RadialMenu.exe --net-job` из папки помощника): один раз UAC, дальше без вопросов. Задание передаётся строкой «действие метка» в `HKCU\Software\MoonRadial` (значение `NetJob`, одноразовое) и выполняется только из фиксированного списка (WinHTTP, маршруты, IP, остатки VPN, DNS, откат брандмауэра, адаптер, глубокий сброс, здоровье дисков, системный PATH, трафик, сон, точка восстановления); системные утилиты - только по полному пути из System32. Журнал задачи начинается с метки запуска - чужой или прошлый журнал не читается.

Проверка без окна: `RadialMenu.exe --net-diag` пишет отчёт в `net_out.txt`. Для отладки работающей копии: `WM_APP+52` - кольцо сети, `WM_APP+53` - карточка обрыва с выдуманной причиной.

## Утилиты

Кольцо «Утилиты» - действие угла `tools` (например, левый верхний), подробности - раздел студии «Утилиты» (вкладки PATH, Диски, Автозагрузка, Порты).

- **PATH и переменные.** Системный и свой PATH по порядку поиска: мёртвые папки, дубли, какие команды находятся в папке первыми. «Что найдётся первым» - какой python, g++, node, cmake и что ими затенено. Свой PATH: выше/ниже/убрать, добавить папку (в кольце - из буфера), «Почистить» (мёртвые и дубли), «Вернуть прошлый». Каждая правка кладёт старый PATH в `%APPDATA%\MoonDesk\tools\path-backups` (копии системного - в папке помощника, см. «Задачи с правами»). Системный PATH через задачу с правами можно только чистить: добавлять туда - значит дать любой программе без прав подсунуть свою папку программам с правами. Переменные окружения: список с мёртвыми путями, свои - записать или удалить.
- **Диски.** Свободное место, здоровье физических дисков (WMI Storage, без прав), износ, температура и часы работы - через задачу с правами (только чтение). «Что занимает место» - размеры папок с переходом внутрь (ссылки не раскрываются). Кэши и временные файлы (TEMP, npm, pnpm, pip, uv, Yarn, NuGet, Go, Gradle, Cargo, дампы, отчёты об ошибках, шейдеры DirectX и NVIDIA, Unreal Engine DDC): размеры и очистка содержимого, занятые файлы пропускаются; чистится только папка из этого списка. В TEMP удаляется то, что старше 6 часов и никем не занято (проба: открыть на удаление без общего доступа); кэш разбора clangd `preamble-*.pch` - уже через час. Одно правило `tools::TempRemovable` и для подсчёта, и для RadialTools: «можно освободить» не обещает занятое и чужое (например, файлы деинсталлятора, созданные с правами администратора). Кто не дал удалить занятое - по Restart Manager (`WhoLocksFiles`), в итоге чистки и журнале. Кэши шейдеров и Unreal собираются заново долго - в «Всё сразу» не входят и чистятся только по отдельности, с вопросом. Размеры в кольце считаются в фоне с низким приоритетом процессора и диска (через минуту после старта; раз в полчаса - PATH; кэши, TEMP, кэш Unreal, мусор проектов, git и снимок роста - раз в 3 часа: обход кэшей - миллионы файлов и ~20 с процессора, весь кэш Unreal и его старое считаются одним обходом; диски WSL, хвосты программ, устройства и обновления - раз в сутки; «Обновить» в студии - всё сразу; в игре и при открытом Unreal Editor подсчёт ждёт), кольцо открывается сразу. «Что занимает место» при настроенной задаче с правами читает таблицу MFT напрямую (`tools/mft.cpp`, только NTFS, только чтение): задача за один проход считает размеры всех папок тома и кладёт таблицу в папку помощника (`Program Files\MoonRadial\data\mft-C.tsv`: читать может пользователь, писать - только администратор, файл заменяется целиком). Пять минут любая папка этого тома, в том числе при переходе внутрь, берётся из неё мгновенно; без свежей таблицы задача зовётся (без UAC) только для диска и папок первого уровня, глубже быстрее обычный обход. Ответ каждый раз сверяется со списком папок и файлами в самой папке, не сошлось - обычный обход. Число файлов в папке должно совпасть; байты MFT больше списка - норма (растущие открытые журналы, `System32\LogFiles\WMI`: размер в списке папки отстаёт, в MFT он настоящий), меньше - только в пределах 1% и мегабайта (`mft_detail::LooseMatch`). Пока студия открыта, разобранная таблица тома держится в памяти (индекс «родитель -> строки», `mft_detail::TableIndex`): переход в папку берёт готовый срез, а не разбирает 25 МБ текста; сбрасывается, когда файл таблицы поменялся, устарел (5 минут) или студия закрылась (`tools::MftForget`). Файлы-ссылки (OneDrive «только в облаке», AppExecLink, symlink) считаются и обходом, и MFT - их EndOfFile; папки-ссылки не раскрываются ни там, ни там. В «можно освободить» (кэши, TEMP, мусор проектов, старое в кэше Unreal) файлы «только в облаке» не идут: места на диске они не занимают. Пока задача читает таблицу, в середине кольца «Читаю таблицу MFT...»; папки, куда обходу нет входа даже с правами (System Volume Information, `System32\LogFiles\WMI\RtBackup` - только для SYSTEM; закрытой считается папка, которая видна в списке, но сама не открывается: на RtBackup Windows не отдаёт даже её атрибуты, так что по коду ошибки не узнать), отмечаются строкой «ещё N в закрытых папках (видно только по MFT)». Задача не настроена или устарела после пересборки - кнопка «Включить быстрый подсчёт» (один запрос UAC, потом тот же подсчёт уже по MFT); антивирус не пускает задачу - обычный обход с объяснением в журнале. Разбор записей (`tools/mft_parse.cpp`, `mft_detail.h`) отдельно от чтения тома и покрыт тестами. Сверка с обходом и с таблицей в кэше: `RadialMenu.exe --mft-test <папка>` из консоли администратора, итог в `mft_out.txt` (программа оконная: консоль возвращается сразу, файл появляется через 10-60 с). Где MFT больше обхода, тест сам спускается по папкам до места разницы: закрытые папки, файлы-ссылки, растущие открытые файлы (их размер в списке папки отстаёт, в MFT он настоящий). Проверено на `C:\Windows`: 4,2 с против 17,8 с обхода, 85 из 87 папок до байта, остальное - закрытые папки и открытые журналы. Загрузки и TEMP под живым наблюдением (`tools/livesize.cpp`, ReadDirectoryChangesW, пересчёт после 2 с тишины и не чаще раза в минуту): рост за сегодня - в «Рост за неделю», TEMP +5 ГБ за час - карточка. Корзина - отдельным сектором, с вопросом. Раз в 10 минут проверка: на диске меньше 10% и меньше 20 ГБ - карточка «Мало места» (`tools_disk_warn`): что можно освободить на этом диске (кэши и TEMP, сборки давних проектов с именами - из последнего фонового подсчёта) и что занимает больше всего (две самые большие папки, если таблица MFT в кэше свежая; обход диска ради карточки не запускается).
- **Автозагрузка.** Run (свой и компьютера), папки «Автозагрузка», задачи планировщика при входе (кроме системных Microsoft). Выключение - как в Диспетчере задач (StartupApproved), ничего не удаляется. Без прав переключается своё; записи для всего компьютера - в Диспетчере задач.
- **Порты и блокировки.** Кто слушает порты (разработческие 3000, 5173, 8080... - первыми); в кольце два клика - «Открыть» http://localhost:порт или «Завершить». Перед завершением проверяется, что номер процесса не достался другой программе, пока кольцо было открыто. Кто держит файл или папку (Restart Manager плюс программы, запущенные из самой папки), в кольце - для пути из буфера, с кнопкой «Завершить».
- **Процессы.** Самые тяжёлые программы этого входа по личной памяти (как столбец «Память» в Диспетчере задач: общие библиотеки не считаются по разу на процесс). «Закрыть» сначала шлёт главным окнам WM_CLOSE (браузер сохранит вкладки, редактор спросит про файлы), через 5 секунд оставшиеся процессы завершаются силой. Системное, антивирус и сам RadialMenu не показываются и не завершаются.
- **PATH в кольце.** Сколько лишних записей и «Почистить», конфликты версий, какой python, pip, node, g++, cmake, git найдётся первым (два клика - показать в Проводнике), «Добавить» папку из буфера.
- **Конфликты версий.** Команда, которая находится в PATH в разных версиях (python 3.10 впереди 3.14, cmake из двух MinGW): версия берётся из ресурса exe, иначе из пути. Если обе папки в своём PATH - два клика поднимают затенённую в начало (с бэкапом). Если впереди системный PATH - подсказка, что нужны права.
- **Мусор проектов.** В папках из колец (и `source\repos`, `Unreal Projects`) ищутся пересобираемые папки: `node_modules`, `.next`/`.turbo`, `Intermediate` и `DerivedDataCache` рядом с `.uproject`, `target` рядом с `Cargo.toml`, `.venv` с `pyvenv.cfg`, `build*` с `CMakeCache.txt`, Gradle, `.NET obj`. Без признака рядом папка не считается мусором. Видно размер и сколько дней в проекте ничего не меняли; «Давние» - всё из проектов без правок дольше 60 дней. Перед удалением RadialTools.exe проверяет признаки заново.
- **Кэш Unreal без потерь.** «Unreal: старое» убирает из общего DDC только файлы, которые не открывались и не менялись 30 дней (время доступа на NTFS включено): шейдеры текущих проектов остаются.
- **Рост за неделю.** Раз в 3 часа фоновый подсчёт пишет размеры кэшей, мусора по проектам, Загрузок, Рабочего стола и Видео в `%APPDATA%\MoonDesk\tools\sizes.tsv` (40 дней). В секторе «Диски» - что выросло сильнее всего; раз в неделю карточка, если что-то выросло больше чем на гигабайт.
- **Память перед игрой и Unreal.** Если Boost не настроен или ему нечего закрыть, а свободно меньше 4 ГБ (или занято больше 80%), карточка покажет самые тяжёлые программы и «Закрыть» для первой - мягко, как в секторе «Процессы». Саму игру и редактор не предлагает.

### RadialTools.exe

Всё, что удаляет файлы и завершает процессы (очистка кэшей, мусор проектов, кэш Unreal, корзина, «Закрыть», «Завершить»), выполняет отдельный `RadialTools.exe` рядом с основным. Постоянно работающий `RadialMenu.exe` сам ничего не удаляет и чужие процессы не трогает: он запускает `RadialTools.exe` по кнопке и читает ход из его вывода. Команды (`src/act/act.cpp`): `clean <имя кэша>`, `ddc-trim <дней>`, `projects <пути>`, `kill <pid> [exe]`, `close <exe> <мс>`, `empty-bin`, `recycle-dup <оставить> <копии>`; каждая проверяет, что ей прислали (только кэши из списка, только папки с признаками сборки, номер процесса того же exe, не системное; системное имя вне папки Windows - самозванец, его завершить можно). Собирается тем же `build.cmd`.

Проверка без окна: `RadialMenu.exe --tools-diag` пишет `tools_out.txt` (PATH, автозагрузка с весом, порты с проектами, кто держит, тяжёлые программы, кэши, мусор проектов, конфликты версий, окружение терминала, драйвер NVIDIA, рост за неделю); `RadialMenu.exe --clean` чистит то же, что «Всё сразу», итог в `clean_out.txt`; `WM_APP+54` открывает кольцо утилит у курсора, `WM_APP+57` - студию с подсчётом «Что занимает место» на C:, `WM_APP+58` - карточку со сценой на выдуманных данных (wParam 0 - очистка, 1 - защита с находками, 2 - всё чисто; ничего не удаляет). Сцены без окна: `--scene-film clean|guard|guard0 out.png` - лист кадров; `RADIAL_SCAN=папка` для `--studio-snap 7 1` сразу считает соты, `RADIAL_SCENE=clean` - выдуманная чистка для снимков студии. `RADIAL_DEMO=1` - выдуманные данные для сцен части 2 (сеть, порты, автозагрузка, колба, батарея, версии; ничего не завершается и не выключается): `--studio-snap 6 0`, `--studio-snap 7 2..5`, `--studio-snap 10 0`. В фильме `RADIAL_FILM` есть «r д» - колесо, `RADIAL_FILM_CROP="x y ш в"` - кадры куском один к одному.

Задачи планировщика лежат в папке `\MoonRadial` (раньше `\MoonDesk`: её однажды испортил откат антивируса - файл задачи остался, а записи в реестре исчезли).

### Задачи с правами

Задачи `RadialMenuNet` и `RadialMenuPurge` выполняются с наивысшими правами без UAC, поэтому запускают не `RadialMenu.exe` из папки программы (её, вместе с DLL рядом, может подменить любая программа пользователя - и молча получить права), а копию-помощника `C:\Program Files\MoonRadial\RadialMenu-<хэш>.exe`: туда пишут только администраторы (`core/elevate`).

- Помощник ставится одним запросом UAC: системный `cmd` с правами копирует `RadialMenu.exe` в Program Files под именем `RadialMenu-<хэш>.exe` (у каждой сборки своё: заменить файл на месте удаётся не всегда), через `schtasks` (пере)создаёт задачу и убирает прежние копии; заодно на помощника переводятся и другие уже созданные задачи. Не сам RadialMenu.exe: Касперский останавливает программу, которая кладёт свой exe в Program Files и тут же заводит на него задачу с наивысшими правами.
- Задачу, созданную администратором, пользователь без прав может только читать - запуск отвечает «параметр задан неверно». Установка явно даёт пользователю «читать и запускать» (не «менять»: иначе любая программа пользователя переписала бы задачу с правами).
- Касперский не даёт планировщику поднимать права неподписанной программе: задача стоит, а не запускается (системный `cmd` в такой же задаче - запускается). Тогда задача помечается (`HKCU\Software\MoonRadial\TaskBlocked-...`), и каждое действие «Сети» и «Утилит» спрашивает одно окно UAC и выполняется тем же помощником - задание из HKCU, журнал в Program Files. Очистка памяти после игры в этом случае пропускается, карточка в студии снова предлагает «Настроить». Чтобы действия шли без вопросов, добавьте `RadialMenu.exe` и `C:\Program Files\MoonRadial` в доверенные программы Касперского и удалите отметку `TaskBlocked-RadialMenuNet` (или нажмите «Пересоздать» у очистки).
- Перед запуском задачи проверяется, что она указывает на помощника и что помощник побайтно совпадает с текущим exe. Нет - «Сеть» и «Утилиты» один раз спрашивают UAC и обновляют его; очистка памяти после игры просто пропускается.
- Процесс с правами ничего не пишет и не удаляет в папках пользователя (подложенная туда ссылка перенаправила бы его запись): журнал задания, бэкапы hosts и брандмауэра, копии системного PATH лежат в `C:\Program Files\MoonRadial\data`. Откат брандмауэра берёт бэкап только оттуда. Пути к системным файлам - от системы, не из переменных окружения.
- Есть ли задача, спрашивается у самого планировщика (`schtasks /Query`): ветку `TaskCache` в HKLM обычный пользователь читать не может.
- «Стоп»: долгие задания (починка Windows, остатки обновлений, сжатие дисков WSL и Docker) идут с кнопкой «Стоп» в карточке, подсчёт «Что занимает место» - с кнопкой студии. `net::RunAdmin(..., cancel)` перестаёт ждать, само задание с правами доработает в фоне; следующее задание сначала дожидается его конца (журнал и задача у них одни), но не дольше своего тайм-аута. Когда брошенное задание закончит, фоновая слежка (`net::SetLeftDone`) пишет итог в журнал автоматики и показывает карточку «...: доделано в фоне» или «не получилось» с последней строкой его журнала.
- Ход DISM и SFC: проценты из их вывода (`tools::LastPercent`, не чаще раза в 2 с и только новое число) приходят строкой «@pct N ...», карточка показывает их строкой хода и полоской.

## Автоматика

Что программа делает сама (`app/autos`), всё выключается в студии: Обзор - Автоматика.

- **Тихая чистка** (`auto_clean`): раз в неделю и сразу, когда на C: меньше 10% и меньше 20 ГБ (не чаще раза в 6 часов) - TEMP (старше 6 часов и не занятое) и быстрые кэши одним запуском RadialTools.exe (`clean <имя>...`). Кэши uv, npm, pip и Go чистятся их собственными командами (`uv cache clean`, `npm cache clean --force`, `pip cache purge`, `go clean -cache`), если программа установлена; иначе - папка напрямую. Файлы удаляются с POSIX-семантикой (имя пропадает сразу, даже если файл кто-то держит). Пустые кэши и TEMP, где только свежее, пропускаются. В игре не запускается. Итог - карточка, если освободилось больше 200 МБ, иначе только журнал.
- **Одна чистка за раз**: кольцо, студия и тихая чистка занимают её через `toolsui::CleanClaim` и делят одну сцену-вихрь. После чистки размеры кэшей в подсчёте сразу обнуляются (остаток занят или свежий), фоновый подсчёт, начатый раньше, их не перетирает.
- **Разбор Загрузок** (`auto_downloads`, `downloads_days`): раз в неделю ищет старые установщики (.exe, .msi), архивы, уже распакованные рядом в папку с тем же именем, копии «файл (1).zip» того же размера, недокачанное (.crdownload, .part) и старые .torrent. Карточка «В Корзину» / «Показать»; удаление - только в Корзину и только файлов из корня Загрузок (RadialTools проверяет).
- **Режим питания** (`auto_power`): ползунок «Режим питания» Windows 11 (наложение схемы, без прав администратора): от батареи - экономия, на зарядке - сбалансированный, игра или режим разработки на зарядке - максимальная производительность, от батареи - сбалансированный. Срабатывает при смене источника питания (GUID_ACDC_POWER_SOURCE) и режимов.
- **Самовосстановление** (`auto_repair`): раз в 15 минут. Пропал автозапуск, а его хотели (отметка `HKCU\Software\MoonRadial\AutostartWanted` ставится при включении и выключении) - задача создаётся заново. `radial.cfg` пропал или пустой - достаётся последняя копия из `backups`. Пропал `RadialTools.exe` - карточка (пересоздать нельзя). Антивирус не обходится.
- **Журнал**: `%APPDATA%\MoonDesk\tools\journal.tsv` (до 64 КБ, дальше уходит в `journal.old.tsv`, одна старая копия; `tools/journal.cpp`), показывается на странице «Автоматика».

## Студия: «Состояние»

Главная страница студии (группа «Обзор»: Состояние | Автоматика | Разделы):

- шкалы дисков и памяти (клик по диску - что его занимает) и текущий режим питания;

TEMP считается честно: в сумму идёт только то, что старше суток, а свежее показывается отдельной строкой;

- рост за неделю столбиками; система: драйвер NVIDIA, здоровье дисков, автозапуск (включить одной кнопкой), самая тяжёлая программа с «Закрыть».
- новое за неделю: что появилось, убрано и обновилось (программы, автозапуск, службы, драйверы, задачи - по снимкам
  раз в сутки), три столбца и фильтр по виду.

Проверка без окна: `RadialMenu.exe --studio-snap 10 0 out.png` (Состояние, размеры считаются перед снимком), `11` - Автоматика.

## Карточки-сообщения

Справа снизу выезжают карточки: Boost, сеть («Пропал интернет», «Выход сменился: Великобритания → Германия»), утилиты, снимок области. Общая основа - `desk/toast`:

- карточки складываются стопкой: новая встаёт над уже открытыми, ушедшая освобождает место, и верхние плавно опускаются;
- въезд справа пружиной с лёгким перелётом, уход вправо с растворением; движение считается по времени, а не по кадрам;
- высота подстраивается под текст (до четырёх строк), знак слева и полоска по смыслу: галочка, крестик, предупреждение, вопрос, сеть, работа;
- полоска внизу показывает, сколько карточке осталось; пока курсор на ней, таймер стоит;
- крестик, правый клик, клик по итогу или бросок вправо убирают карточку; фокус у игры не отнимается.

Для проверки: `WM_APP+53` - карточка обрыва с кнопками, `WM_APP+55` - стопка (смена выхода и итог Boost), `WM_APP+56` - карточка снимка с кусочком экрана.

## Автозапуск и память

- «Запускать вместе с Windows» (трей или студия, раздел «Поведение») создаёт задачу планировщика `MoonRadial\RadialMenuLogon` «при входе» (старое имя `RadialMenuStart` сломал Kaspersky: файл задачи остался без записи в реестре, без прав его не убрать; включить заново можно и командой `RadialMenu.exe --autostart-on`): она стартует раньше программ из `Run`, с обычным приоритетом, и портал после включения успевает показаться. Прав администратора не нужно. Если планировщик недоступен, используется `HKCU\...\Run`; старая запись из `Run` при запуске переносится в задачу сама, а если exe переехал, путь обновляется.
- Выключение автозапуска в Диспетчере задач учитывается: переключатель покажет «выключено».
- Память в простое: после закрытия кольца, студии, панели, снимка или карточки через несколько секунд кучи сжимаются и рабочий набор отдаётся системе (`core/mem`). Пока кольцо открыто, обрезка ждёт. В покое около 2-4 МБ рабочего набора.
- Перехват мыши всей системы один на всех (углы, двойной клик по столу, прозрачность окон) и живёт в своём потоке (`core/llmouse`): мышь не подтормаживает, пока основной поток занят студией или значками. Ставится, только когда нужен: колесо в углах назначено, двойной клик по столу или Alt + колесо включены; в игровом режиме снят целиком. Своё кольцо держит отдельный перехват, только пока оно открыто.

## Radial Studio

Двойной клик по значку в трее (или `RadialMenu.exe --editor`) открывает студию. Слева пять групп, внутри группы - вкладки над страницей, группа помнит последнюю вкладку:

- **Обзор** (вкладка «Разделы») - карта экрана: маленький монитор, на котором видно, где программа живёт. Обои - картинка темы. У краёв - ручки колец: наведи, и значки секторов выезжают из края; если у сектора пропал путь, ручка жёлтая и тихо дышит, щелчок ищет папку, нашлась - ручка вспыхивает зелёным. Уголки цвета акцента - горячие углы, наведение подписывает действие угла. Окно посреди экрана - тема (его рамка и есть рамка окон): имя, настроение, четыре цвета и шесть миниатюр; наведение - вся студия примеряет тему, щелчок - новая тема расходится волной от миниатюры. Панель задач: сеть с задержкой, игровой режим и автозапуск переключаются щелчком, выключенный автозапуск - с меткой. Под монитором полка: диски полосой, PATH с меткой (щелчок чистит мёртвые записи и дубли), утилиты. При входе экран загорается полосой, обои проявляются, выезжают ручки, загораются углы, появляется окно; в игровом режиме всё сразу на местах.
- **Кольца**: Кольца | Темы. **Стол**: Углы и панель | Красота | Система. **Сервис**: Сеть | Утилиты. **Настройки**: Поведение | Клавиши.

Пока курсор ждёт в горячем углу, рядом проступает название действия («Кольцо сети», «Показать рабочий стол»). В кольцах сети и утилит по шесть групп; редкие действия (прокси-процессы, обновление IP, автозагрузка, системный PATH) - в студии. В длинных списках студии (PATH, порты, «Что занимает место») кнопки строки появляются при наведении на неё.

Проверка без окна: `RadialMenu.exe --studio-snap раздел вкладка файл.png [мс]` рисует раздел студии в картинку (номер раздела - из enum Page в studio_internal.h).

- **Кольца**: оба края видны сразу - две дорожки «Левый край» и «Правый край», секторы на них карточками. Карточку тянут мышью: соседи расступаются пружиной, на соседней дорожке - переезд на другой край, брошенная на другую карточку - слипаются в группу «Новая группа» (имя печатается само, потом сразу можно переименовать; брошенная на группу или папку - становится её пунктом). У группы стопка теней, щелчок раскрывает пункты веером; пункт, вытащенный на дорожку, - отдельный сектор. Сектор с пропавшим путём - с трещиной, вздрагивает, на нём кнопка «найти». Папка из Проводника влетает в то место дорожки, куда её отпустили. Удалить - бросить в корзину под дорожками: карточка рассыпается крошками, «Вернуть» на всплывашке или Ctrl+Z собирает её на прежнем месте. Над корзиной - лента правок: каждая правка - точка, тянешь красную точку назад - правки откатываются на глазах, вперёд - возвращаются.
- Выбранная карточка взлетает в заголовок справа, поля вкладки выезжают по очереди. Вкладки «Основное», «Второе кольцо», «Значок» живые: путь разбирается на звенья (есть - зелёные, где оборвался - жёлтые) с подсказками похожих папок, щелчок по подсказке чинит; второе кольцо показано, как его соберёт меню, - плашки сыплются из папки, щелчок закрепляет плашку первой (закреплённую - открепляет), красная черта - сколько влезет сразу, обычные файлы - с пунктирной рамкой; значки программы - док: ближние к курсору крупнее, значок тянется к квадрату и притягивается, старый растворяется, новый подпрыгивает.
- **Темы** - тема в деле: 12 тем с пейзажами (палитры из cpp-docs-panel, «Лунная ночь», «Из обоев», «Своя палитра»), тема красит и кольца, и саму студию. Слева витрина выбранной темы с палитрой и кодами цветов, справа - как она ляжет: кусочек студии, рамка и заголовок активного окна, карточка-сообщение. Внизу лента тем доком (ближние к курсору крупнее), «Из обоев» и «Своя палитра» - за чертой в той же ленте; у своей палитры цвета меняются щелчком по квадратам витрины. Наведение - примерка: картинка растворяется с медленным наездом, цвета перетекают, «Сейчас» становится «Примерка». Щелчок - новая тема проступает волной от карточки по всему окну.
- **Поведение**: где открывать, стекло, размер, звук, терминал, автозапуск.
- **Система**: значки папок, центр уведомлений, фон Пуска, курсор, заряд, ночной режим, двойной клик по столу, карточка снимка.
- **Стол**: три действия на каждый угол (задержка, двойной толчок, колесо), запись сочетаний клавиш, панель «Сейчас играет» и карточка при смене трека.
- **Красота**: скорость движения, рамки и заголовки окон, игровой режим (что выключать, маски игр, текущее состояние), экран блокировки и просмотр перехода.
- **Клавиши**: шпаргалка по управлению меню.

Управление в студии:

| действие | что делает |
|---|---|
| ПКМ по сектору | меню: переименовать, выше, ниже, на другой край, дублировать, удалить |
| двойной клик по названию, F2 | переименовать прямо в списке |
| тянуть сектор | поменять порядок; на кнопку другого края - перенести туда; на середину простого сектора - сделать пунктом |
| тянуть пункт второго кольца в список | сделать отдельным сектором |
| стрелки, Alt+стрелки | выбрать сектор, сдвинуть сектор |
| Delete, Ctrl+D | удалить, дублировать |
| Ctrl+Z, Ctrl+Y | отменить, вернуть |
| наведение на тему | примерить её на студию |

После удаления и переносов внизу на 5 секунд всплывает уведомление с кнопкой «Отменить». В списке помечаются секторы с пропавшим путём, без пути и с «раскрытием» не папки. Перед сохранением студия делает резервную копию `radial.cfg` в `backups\` (до 10 штук, не чаще раза в 10 минут), вернуть её можно из «Журнала».

Всё сохраняется само в `radial.cfg`, «Отменить» внизу (или Ctrl+Z) откатывает последнее изменение, «Журнал» показывает историю. «Показать меню» открывает кольцо у края для проверки.

## Сборка

```
build.cmd
```

Нужны MSYS2 ucrt64 (`g++`, `cmake`, `ninja`) в `D:\msys64`. Готовый `RadialMenu.exe` появляется в корне проекта рядом с `radial.cfg`.

Линкер пишет exe в `<папка сборки>\link`, а в рабочую папку он попадает только целым (`cmake/deploy.cmake`): проверка, что файл не пустой и начинается с `MZ`, копия рядом в `RadialMenu.exe.new`, её проверка и замена одним переименованием. Прерванная сборка больше не оставляет `RadialMenu.exe` в 0 байт: старый exe остаётся, а сборка падает с сообщением «Сборка испорчена: ...». Потом подпись (`cmake/sign.cmake`, если настроена) и отметка целостности (`cmake/integrity.cmake`) - уже с выложенного файла.

`radial.cfg` у каждого свой и в репозиторий не входит: при первом запуске он копируется из `radial.example.cfg`
(кольца с Документами, Загрузками, Музыкой и другими общими папками), дальше всё настраивается в студии.

Проверочная сборка, не останавливая работающую копию: `cmake -S . -B build-check -G Ninja -DRADIAL_OUT_DIR=build-check`,
потом `cmake --build build-check`.

Свой код собирается с `-Werror`: любое предупреждение (например, `L"\*"` - неизвестная escape-последовательность) ломает сборку.

Тесты без окон (`tests/tests.cpp`: правило TEMP, разбор хода чистки, обход папок и папки-ссылки, живой рост, разбор MFT на синтетических записях - исправления секторов, куски с отрицательным смещением и разреженные, DOS- и Win32-имена, жёсткие ссылки, записи-продолжения, ссылки, таблица папок, её файл и индекс в памяти, сверка файлов в корне, вывод DISM и проценты хода, ротация журнала, находки автозапуска, дампы падений, рост своей памяти, фоновые задачи):

```
build.cmd test
```

собирает и прогоняет их, не трогая работающий `RadialMenu.exe`; упали - код ошибки. Вручную: `cmake --build build-check --target radial_tests`, потом `ctest --test-dir build-check`.

```
build.cmd lint
build.cmd snaps
```

`lint` - clang-tidy по всему `src` (проверки на ошибки из `.clang-tidy`, без стиля). `snaps` - эталонные снимки студии:
восемь разделов (среди них вкладки «Утилит» PATH и «Диски») и кольцо утилит с раскрытой «Защитой» (`--tools-ring-snap
файл 4 demo` - выдуманные пункты) снимаются в `build-check` с выдуманными данными (`RADIAL_DEMO=1`) и сравниваются с `tests\snaps`
попиксельно (порог 0,5%); разница - картинкой `build-check\snaps\<раздел>-diff.png`, итог - `snaps_out.txt`.
`build.cmd snaps update` - записать нынешние снимки как эталоны.

Отладочные сообщения окну программы (`WM_APP + 50..58`, `66..68`: кольца, портал, карточки на выдуманных данных)
принимаются только при `RADIAL_DEV=1` или файле `dev.on` рядом с exe - иначе их мог бы послать любой процесс.

Установщик для других людей - набор `radialmenu` в Moon bundle (`D:\Desktop\components\moon-bundle`):
`node build.js radialmenu --test` (проверка в песочнице; работающую RadialMenu на время закрыть - установщик
ждёт её закрытия), архив - `dist\radialmenu-install.zip`. Свой `radial.cfg`, бэкапы, исходники и картинки `art` в
него не попадают.

### Падения

Необработанное исключение, `std::terminate` и `abort` пишут минидамп (`MiniDumpWriteDump`, dbghelp только из System32) и строку «код, что это, модуль+смещение» рядом в `%APPDATA%\MoonDesk\crash\crash-<дата>-<время>-<pid>.dmp/.txt`, хранятся последние 5 (`core/crash`). При следующем запуске - строка в журнале автоматики и карточка «Программа падала» с кнопкой «Папка»; о каждом дампе - один раз (отметка `reported` в той же папке). Проверка: `RadialMenu.exe --crash-test` нарочно падает. После падения (если программа прожила больше минуты) поднимается новая копия с `--after-crash` - она ждёт, пока старая освободит мьютекс; при обычном выходе и конце сеанса перезапуск выключается первым делом, а сам выход - `TerminateProcess` после `ShutdownAll`, без разрушения глобальных объектов (они держали картинки GDI+ и падали в gdiplus.dll). Вторая обычная копия рядом с работающей сразу выходит.

Своя память: слежка раз в час пишет в журнал автоматики рабочий набор, частные байты, число дескрипторов, GDI- и USER-объектов (`tools/selfwatch`); за сутки частные байты выросли больше чем на 300 МБ, дескрипторы на 3000 или GDI/USER на 1500 - карточка «RadialMenu растёт» (не чаще раза в сутки, не в игре).

Разбор адреса: сборка, пока exe ещё с символами, пишет карту `nm` в
`%APPDATA%\MoonDesk\integrity\maps\RadialMenu-<метка>.map` (10 последних, `cmake/symbols.cmake`), потом убирает
символы из exe. Строка падения несёт ту же метку («... в RadialMenu.exe+0x4fd40, сборка 6ADA197A» - TimeDateStamp
заголовка PE), карточка «Программа падала» и журнал автоматики сразу пишут функцию («функция devcli::Run(int&)+0xf60»).
Вручную: `RadialMenu.exe --crash-decode ["строка"]` -> `crash_out.txt` (без строки - все падения из папки crash).

Код и смещение падения - ещё и в журнале Windows (Приложение, событие 1000). Сборка с символами для разбора адреса:
`cmake -S . -B build-sym -G Ninja -DRADIAL_STRIP=OFF -DRADIAL_OUT_DIR=<папка>`, затем `nm -C --defined-only` и ближайший
адрес ниже `0x140000000 + смещение`. Студия не рисует кадр внутри кадра: COM и WMI (здоровье дисков, планировщик)
прокачивают сообщения, вложенный WM_PAINT откладывается; WMI - в своём потоке.

### Замеры

`set RADIAL_PROFILE=1` перед запуском: при выходе рядом с exe появится `profile.log` со временем основных операций
(кадр меню, открытие, снимок под стекло, кадр студии по разделам, `poll` - такт опроса основного потока). Строки
`cpu.*` - время процессора фоновых проходов, а не настенное (`PERF_CPU`): `cpu.scan` - подсчёт места, `cpu.security` -
«Защита», `cpu.guard` - проход сторожей процессов, `cpu.watch` - минутная слежка.

`set RADIAL_SNAP=1`: каждый кадр панели «Сейчас играет» сохраняется в `media_snap.png` рядом с exe.
